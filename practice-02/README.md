## 4. Модель данных и функции

Задача — объект `{ id, title, completed, priority }`:

- `id` — положительное безопасное целое число (`Number.isSafeInteger(id) && id > 0`), строки не преобразуются;
- `title` — строка, после `trim()` длина от 1 до 100, в объект записывается очищенная строка;
- `completed` — `true` / `false`, у новой задачи всегда `false`;
- `priority` — строго `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`.

Распределение ответственности:

| Файл | Назначение |
|---|---|
| `src/data.js` | Общий набор `demoTasks`, номер и задачи варианта. |
| `src/task-service.js` | Девять функций и две внутренние проверки (`validateId`, `normalizeTitle`). Без вывода в консоль и без глобального списка. |
| `src/main.js` | Импорт данных и функций, общий сценарий и сценарий варианта, вывод результатов и ошибок. |
| `checks.js` | 35 готовых проверок и 3 собственные. |

| Функция | Успех | Ошибка / отсутствие |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект | `undefined` |
| `getPendingTasks`, `getTaskTitles` | новый массив | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks }` (новый массив) | `{ ok: false, error }` |

**Почему id не равен индексу:** индекс — текущая позиция элемента в массиве, он меняется при удалении соседних записей. `id` — постоянный идентификатор записи. Например, в `demoTasks` задача `id = 4` лежит по индексу 1, а `tasks[4]` вообще не существует.  
**Почему getTaskStats возвращает число, а не строку с процентом:** с числом можно продолжать вычисления и сравнения, а округление — это вопрос отображения. Поэтому `toFixed(1)` вызывается только в `main.js`.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив (через `map`) и новый объект изменяемой задачи (через `{ ...task, поле: значение }`). Неизменённые задачи переиспользуются без изменений.
